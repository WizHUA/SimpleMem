# 三路条件检索

三路技术均为通用方法：词法路使用 FTS5 候选与 BM25，符号路精确匹配主体和属性，语义路使用配置的 Embedding 与余弦相似度。MemNexus 的实现重点是结合短期优先、证据约束和动态预算选择执行路径。没有新增依赖、路由模型、服务或常驻线程池。

## 执行规则

| 问题与条件 | 执行路径 |
|---|---|
| 明确单字段查值，主体/属性出现在原问题中，移除字段和常见问句后无额外要求，且合格记录中存在精确匹配 | 词法 + 符号；跳过语义，使用一次本地线程调度 |
| 方案、比较、汇总、多信息项、多条不同语义查询 | 有词项时执行词法；有完整字段时执行符号；配置向量服务时执行语义，各路并发 |
| 开放问答或带历史/时点约束的问题 | 按同样的可用条件选择通道，时间约束先过滤；只问明确字段的时点查询仍可走本地路径 |
| 规划字段没有匹配记录 | 保留权限、状态和有效期，放宽字段过滤；恢复词法与可用语义召回，符号路如实记录零命中 |
| 未配置向量服务 | 语义标记 disabled；本地词法与符号合并到一次工作线程调度 |
| 空查询、零上限、不需记忆、无合格记录或候选预算耗尽 | 不执行相应召回，记录原因 |

问题类型取自已有 `QueryPlan` 和少量确定性规则。分类偏保守：不满足完整单字段条件时保留语义机会。该规则不是语义充分性证明，也不以低召回分数推断事实真假。多信息项查询继续避免用一个符号字段过滤掉其他信息项。

短期与长期仍依次执行。只有当前短期精确单字段且全部合格记录取值唯一时才省略长期补充；冲突值、历史与时点查询继续补查。未配置向量服务时仍为 `lexical_baseline`，配置后的 `hybrid` 表示能力模式，是否实际调用需查看通道状态。

## 并发和开销

语义检索的网络等待与本地 FTS/BM25、符号匹配重叠。每个记忆层最多三个任务，使用现有 asyncio 默认线程池。没有向量请求的本地路径只调度一个工作线程，避免为极短的精确匹配单独创建并发任务。

各路仅返回独立结果，完成后按固定顺序融合，按记忆 ID 与版本去重并保留命中通道。原有最大归一化分数、候选上限、证据链、冲突提示和字符预算继续生效。没有新增融合参数，也没有把相似度改称置信度。

请求仍共用一个期限，覆盖排队、规划、投影和召回。一条通道失败时取消其他异步任务，并保留原始异常类型供 SDK 处理。Python 不能强行中断已经运行的工作线程；其结果不写共享融合状态，投影读写仍由锁和代次检查保护。同一命名空间继续串行保护快照一致性。

每个 `RetrievalChannel` 新增向后兼容的 `elapsed_ms`，旧数据默认为 0。`query_conditions` 提供 `query_type`、`active_views` 和 `execution_mode`；语义按需跳过时为 `status=skipped`、`detail=exact_field_lookup`。本地计时从工作线程开始执行算起，语义计时包含投影、向量服务等待与评分；各路可能重叠，不能相加充当请求总耗时。前端能区分按需跳过与未配置服务。

## 验证与性能

2026-09-19，在 `simplemem-agentmemory` 环境完成后端全套 216 项测试。新增覆盖单字段零向量调用、字段失配回退、多信息项与时间查询、比较问题的跨字段召回、三个通道的执行屏障、重复语义查询去重、无词项查询、确定性融合、超时及失败取消。原有租户/会话隔离、有效期、版本、删库代次和 SDK 错误契约测试通过。Ruff 检查与格式检查、TypeScript/Vite 构建通过；Playwright 的 6 项检索相关测试通过，包括按需跳过、历史状态和窄屏展示。

可复现实验命令（从 `memory-system` 执行）：

```powershell
conda run --no-capture-output -n simplemem-agentmemory python scripts/benchmark_retrieval_routes.py --output docs/RETRIEVAL_ROUTES_BENCHMARK.json
```

实验使用 500 条合成长期记忆、真实内存 SQLite FTS/BM25、投影与融合逻辑，预热后各执行 7 次，Embedding 为固定向量和 40 ms 模拟等待。三种方式均检查最终证据 ID 和分数一致。原始样本见 [JSON 记录](RETRIEVAL_ROUTES_BENCHMARK.json)。

| 问题 | 等待本地完成后调用语义的对照 | 全通道并发 | 条件执行 | 条件执行的向量调用 |
|---|---:|---:|---:|---:|
| 项目截止日期是什么 | 76.584 ms | 62.042 ms | 12.914 ms | 0/7 次 |
| 项目截止日期有哪些影响 | 62.112 ms | 62.700 ms | 62.444 ms | 7/7 次 |

这里最明确的收益是精确问题省去了不必要的向量工作。开放问题没有测出稳定提速：本地候选已经较少，线程调度和平台计时波动可抵消重叠收益。执行屏障测试证明了真正并发，但并发本身不保证每个查询更快。

上述对照是调度消融，不是旧版整体性能；固定向量不能评估真实语义召回质量。当前仍扫描授权快照，向量召回仍是精确余弦遍历而非 ANN。CPU 密集步骤受 GIL 和共享 SQLite 锁约束，多用户吞吐及真实服务延迟仍需在目标数据和向量服务上测量。
