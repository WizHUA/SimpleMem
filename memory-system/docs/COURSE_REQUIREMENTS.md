课程评分为平时表现 10%、PPT 与系统演示 40%、报告/代码/视频 50%。因此交付既需要讲清机制，也必须保留可重跑的代码证据和真实宿主验收记录。

目前已提供超过八千汉字的[技术报告](技术报告.md)和[二十分钟演示脚本](答辩演示脚本.md)。[真实模型小样本](LIVE_SMOKE.md)已完成抽取、两条长期记忆、跨会话召回和热缓存命中。[本地效果与性能](EVALUATION.md)及[HTTP 负载](HTTP_LOAD.md)分别记录合成基线和进程内并发结果。公开数据集质量、真实宿主集成及最终 PPT/视频不由这些成果替代。

[真实十题小集](LIVE_QUALITY.md)补充直接回忆、改写、多事实、未知拒猜、隔离与更正用例。初次失败记录保留，修复复测严格规则为 9/10；单题非盲复核不改变自动分数。该材料适合解释如何从真实失败定位工程问题，不适合宣称通用问答准确率。

## 保留的设计主线

现有 `output/长短期记忆系统方案汇报/当前设计与框架.md` 定义两条链：在线查询按 SimpleMem 思路进行意图规划、STM 优先、多视图检索和动态预算；离线维护从交互产生候选，再通过来源约束、版本与有效期执行记忆演化。继续沿用该边界。H-MEM 分组目前是引用组织视图，不能写成已实现完整层级语义索引。没有 embedding 时的词法基线也不能写成语义向量检索。

演示与测试采用普通项目协作、会议安排、偏好纠正等合成内容，验证通用记忆能力。SDK 适配层只输出记忆检索与生成结果，不承担宿主任务规划或专业决策。

## 建议答辩顺序

1. 创建会话，输入目标和约束，展示 STM 原始轮次与窗口预算。
2. 抽取原子候选，点开来源；模型未配置时展示明确的不可用状态。
3. 提升为 LTM，新建会话检索，展示跨会话复用和隔离边界。
4. 修正事实并替代旧版本，展示最新结果、历史版本和审计。
5. 对同一问题进行冷/热请求，并在写入新事实后重试，展示缓存失效与正确性。
6. 展示评测结果及失败/缺失项；区分独立系统演示、SDK 形状测试与真实宿主集成。
