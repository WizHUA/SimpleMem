## 演示数据

会话一可以设置为“准备项目季度评审”。依次写入“报告默认使用中文”“评审时间暂定周四下午”“输出不包含客户个人信息”“测试环境使用 Python 3.12”“评审时间改为周五上午，以本条为准”。每次写入保存独立 request_id。演示事实修改时点开旧事实来源，确保观众能看见变化依据。只有模型实际抽取成功后才展示其候选结果。

会话二继续同一项目，询问“评审时间和报告语言是什么”。再使用另一个授权范围查询，确认无法看到前一个用户的记录。项目范围与用户范围要按真实数据契约设置，避免把用户级偏好在跨项目复用误判为项目隔离失败。历史查询可询问“评审时间曾经如何调整”，并与当前事实查询并排展示。

## 当前环境的诚实演示方式

真实模型首次请求曾返回 HTTP 402，用户恢复上游可用性后复测已通过，见 [LIVE_SMOKE.md](LIVE_SMOKE.md)。可以展示实际抽取的两条长期记忆、跨会话中文偏好回答与热缓存命中。基线、冷、热请求分别为 2127.1、1559.5、745.8 毫秒，必须标注单次小样本，不用它推导通用加速倍率。合成消融另用 EVALUATION 数据，HTTP 并发另用 HTTP_LOAD 数据。现场若再次发生上游错误，应展示真实错误及水位保留，不能通过静态前端数据伪装成功。

课程真实宿主不在当前资料包中。可展示 SDK 适配代码、独立契约测试和正式验证脚本。正式录制的标题应写“SDK 适配与待验收接入步骤”，不能写“已接入宿主”。获得宿主后补录引擎注册、带身份检索和 SSE 三段，形成最终集成证据。

真实质量小集可用作失败分析示例。先展示初次 7/10，再说明事实目录、日期约束和多字段召回修复，最后展示复测严格规则 9/10。第九题正确回答新日期并解释旧日期，因禁止旧日期的保守规则判错；来源显示新版本二有效。说明这是开发代理非盲复核，不改自动分数、不宣称 10/10，也不将十题对比表述为统计显著提升。

## 质询要点

**为什么没有把所有历史直接放进模型？** 历史长度持续增加，会消耗输入预算并混入旧状态。系统保存原始证据，但只选取当前任务相关记忆和受限近期轮次进入回答。预算目前是字符保守估计，未宣称真实计费 token。

**STM 和 LTM 的区别是什么？** STM 服务当前会话工作状态，LTM 服务跨会话复用。长期提升需要适用范围、来源和维护规则；某段文本较长或较早并不会自动让它成为长期记忆。

**你们复现了哪些论文结果？** 继承已有 SimpleMem 查询规划和压缩思路，并参考版本化与组织方法。当前结果来自本项目测试和合成评测；没有按原论文全协议运行的指标，不作为论文复现成绩展示。

**为什么演化暂时需要显式操作？** 先稳定来源、版本和状态约束，避免未校准模型直接覆盖事实。未来分类器输出受约束命令，继续由确定性存储提交。

**推理加速到底加速了哪里？** 完整输入相同的请求复用已完成生成，并发重复请求共享进行中的生成。没有加速模型内部算子；第一次生成仍然需要模型。收益由工作负载命中率决定。

**缓存会不会返回已经过期的答案？** 每次先授权与检索，再依据完整输入和来源版本计算键。不同用户、会话和改变的证据不会只因查询相同而复用。测试还要覆盖替代、撤回、删除和并发取消。多实例失效传播尚未验证。

**为什么分数为零到一还不能称为置信度？** 它满足宿主融合范围契约，但词法重叠和余弦相似度都有各自含义。没有做概率校准时，零点八不能解释为百分之八十正确概率。

**合成实验能证明什么？** 能证明幂等、隔离、缓存调用计数等受控行为，也能发现特定检索失败。不能证明真实用户任务正确率，也不能把设定的二十五毫秒测试延迟称为真实模型耗时。

**已经达到商用了吗？** 当前是可部署、可测试的交付候选。生产还需要真实认证、目标负载、备份恢复、宿主与真实模型验收。单实例 SQLite 和词法扫描的限制在报告中明确列出。

**如何保证宿主接口不阻塞？** 存储等同步工作经线程卸载，模型走异步端口。请求设超时并传播取消；已经运行的同步线程不能被异步取消强行终止，外部依赖仍需自身超时。

**流式为什么只有一个文本事件？** 当前为 SDK 缓冲兼容模式，完整答案后一次发送。界面与文档明确说明，不把它称为逐 token 流。后续可替换模型流接口，同时保留事件和唯一终止约束。

**最优先的下一步是什么？** 真实模型小样本闭环已经通过；继续完成真实宿主验收，并使用独立长期对话数据评估质量。根据扫描规模实验接入候选索引，保留现有来源、有效期和版本过滤作为最终判断。实际 embedding 接口已实现，但本次真实模型冒烟不包含嵌入服务质量验收。

运行最后一次完整回归和前端构建；使用新建临时数据目录；确认前端无密钥；打开需要的来源和历史页面；记录环境、时间和代码版本。录制时保留实际请求耗时及状态，不通过剪辑改变冷/热顺序。最终视频附运行命令与对应评测文件，确保评审能够重现主要步骤。
