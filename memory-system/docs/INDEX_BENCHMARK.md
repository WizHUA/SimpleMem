# 检索投影实现与实测

检索已接入可重建的 SQLite FTS5 投影。权威记忆仍来自主库，投影不决定用户权限、记忆状态或有效时间。

- 中文二元字组与英文词项先进入 FTS5；查询先取得候选，再执行 Python BM25、层级辅助匹配和实体证据链选择。
- 仅新增或文本变化的记录重新分词。删除和版本变化会清理旧投影记录；历史版本只在权威快照允许时参与检索。
- 向量按文本摘要、模型名、接口地址及 `MEMORY_EMBEDDING_REVISION` 缓存到投影库。相同文本重启后仍可复用；模型权重原地变化时应调整 revision。
- 投影按租户、用户、会话分区。相同分区的同步和检索串行执行，避免旧快照覆盖正在使用的新快照；不同会话可以并行。
- 删除用户时清理该用户全部会话投影，并提升失效代数，阻止清除前已发出的嵌入请求重新写入。主库仍会在返回前复验版本。
- `RetrievalProjection.rebuild(...)` 可从授权快照重建一个分区。投影库不应被当作唯一数据备份。

运行命令：

```powershell
conda run --no-capture-output -n simplemem-agentmemory python scripts/benchmark_projection.py --size 10000 --repeats 5
```

本次使用 10,000 条合成项目记忆，查询“海棠红”，对照组保留同一检索器的过滤、BM25、证据链与选择流程，但让全部文档进入 Python BM25。两组均命中同一条目标记忆。

| 指标 | 实测结果 |
|---|---:|
| 全量扫描与 Python BM25，中位耗时 | 1152.44 ms |
| FTS 暖投影完整检索，中位耗时 | 177.07 ms |
| 首次建立 FTS 投影并检索 | 914.90 ms |
| Python 精排文档数 | 10,000 → 1 |
| 模拟 embedding 冷请求输入数 | 10,001（查询 + 文档） |
| 模拟 embedding 暖请求输入数 | 1（查询） |

原始逐次结果见 [INDEX_BENCHMARK.json](INDEX_BENCHMARK.json)。以上是本机选择性查询的小样本结果，没有真实模型网络耗时，不能解释为通用吞吐量或真实模型加速倍率。

当前仍读取并校验整个授权快照，向量相似度仍扫描所有符合条件的缓存向量；没有实现 ANN。每个会话保存自己的投影也会重复存储长期记忆，在大量会话场景中需要进一步设计共享只读索引和快照引用。常见词查询的候选缩减幅度可能明显小于本次示例。
