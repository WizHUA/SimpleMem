# 基于 SimpleMem 思路的长短期记忆系统设计、实现与验证

本文是课程工程研究报告正文草稿。依据本地课程资料、既有方案及 `memory-system` 实现撰写。代码行为、设计理由和建议实验分别表述。未运行的实验不填入结果，真实宿主集成状态单独说明。最终提交时应附上实际交付版本号、完整评测原始数据、作者分工和学校要求的封面。

## 摘要

长期使用智能体时，交互历史会持续增长，而单次模型输入受到长度和费用约束。原始对话还包含计划、猜测、工具观察和用户纠正，不能直接作为同等可信的长期事实保存。本项目以已有 SimpleMem 实现和长短期记忆方案为基础，构建独立记忆后端与展示前端。系统将会话状态、近期交互和滚动摘要组织为短期记忆，将有来源且可维护的原子事实组织为长期记忆。在线路径按查询意图选择记忆范围，并控制候选数量和上下文预算。维护路径在有限窗口中抽取候选，通过显式演化动作完成提升、合并、替代和撤回。身份范围、来源校验及版本检查由确定性代码执行。

在工程实现上，核心运行时供 HTTP 接口和课程 SDK 适配器共用。SQLite 保存会话、记忆版本及审计信息，模型调用经可替换端口接入。系统额外实现完整上下文一致时的推理结果复用和并发请求共享，并输出可展示的加速轨迹。测试覆盖数据幂等、隔离、版本冲突、超时、取消和接口契约。当前独立实现与测试能够验证这些工程行为；真实宿主验收及公开长期对话基准仍需在相应环境执行。本文给出复现实验口径与发布门槛，避免把接口测试、合成样本或缓存命中直接解释为通用任务质量提升。

关键词为智能体记忆、短期记忆、长期记忆、来源追溯、上下文复用和系统集成。

## 1 研究任务与需求依据

### 1.1 课程任务的实际范围

课程总体设计将长短期记忆列为独立子课题。其核心问题是会话内工作状态保持、跨会话经验固化复用，以及动态更新和遗忘。该任务要求系统同时解决写入与读取。仅有向量检索无法说明新事实如何替代旧事实，仅有对话摘要也无法保证跨会话检索。因此，本项目把持续运行的记忆生命周期作为主线，而不把全部开发工作收缩为一个问答页面。

课程对成果形式也有明确要求。总体设计第 2 页列出正文不少于八千字的研究报告、可复现算法代码、系统集成验证和答辩材料。第 6 页将汇报与系统演示计为百分之四十，将报告、代码和视频计为百分之五十。创新点和集成效果属于评价重点。由此确定，前端需要解释后端机制，实验需要保留原始证据，适配器需要对接课程契约。三者不能互相替代。

已有设计已经确定两条相互配合的执行路径。在线查询路径完成意图规划、按需检索、上下文组装及回答。维护路径完成候选生成、关系判断、版本更新及长期组织。继续开发时保留这两条路径，并明确哪些阶段依赖模型，哪些阶段由规则或事务决定。这样的拆分可以让课程宿主只调用必要能力，也便于独立测试后端。

### 1.2 问题定义

设一次交互属于租户、用户和会话三个范围。系统需要保存该会话的目标、约束、近期交互和已形成事实。给定新的查询，检索结果既应支持当前任务，也应避免引入失效、无来源或越权信息。随着事实变化，系统还要保留变化过程，使用户能够区分过去成立的结论和当前有效的结论。这些要求共同决定了记忆不能简化为若干文本片段。

本项目关注四类可验证问题。第一类是容量约束，要求历史增长时单次抽取和回答输入仍然有界。第二类是状态正确性，要求重试、并发和失败不会破坏记忆版本。第三类是可解释性，要求每条记忆及回答依据能够追溯。第四类是接口适配，要求独立后端以合适粒度嵌入课程 Engine。推理加速作为附加研究点，必须在这些约束之内实现。

### 1.3 非功能要求与实现边界

系统需要在模型未配置时仍能启动，并允许保存和检索近期原文。抽取和生成依赖模型，缺少依赖时应返回明确错误。这样可以把存储故障、模型配置故障和检索空结果区分开，避免在展示时用固定答案掩盖问题。网络错误也不能被改写为空列表，否则宿主无法判断是否应熔断或重试。

当前后端采用单实例 SQLite 存储，适合本地演示、受控部署和中小规模数据验证。检索实现仍会读取授权范围内的数据，再执行筛选和排序。候选预算限制的是保留的结果，不等价于数据库扫描复杂度受限。大型记忆库、跨实例一致性和分布式缓存需要额外设计，本文不把它们列为已完成能力。

## 2 设计依据与技术取舍

### 2.1 从现有 SimpleMem 方案保留的思想

本项目沿用已有方案中对 SimpleMem 的工程理解。交互历史先被整理为可检索的原子记忆，再根据查询意图选择检索方式与预算。实现中保留语义、词法和符号三个视图的接口。语义视图依赖实际嵌入器，词法视图覆盖文本匹配，符号视图利用主体、谓词和实体信息。多视图共同服务于当前查询，而不是为每个问题强制执行同样深度的搜索。

上述继承属于设计和实现路径，不能直接当作对原论文实验的复现结论。原论文数据、模型、超参数和评测协议与本项目未必一致。本文只对当前代码已经执行的行为作出工程判断。若后续需要报告论文复现结果，应固定原仓库提交和数据集，再单独记录实验差异，避免把本项目功能测试混入论文指标。

### 2.2 短期、长期与历史的不同职责

短期记忆保存任务进行中的工作状态。它包含当前目标、计划、约束、摘要以及近期交互。其主要约束是容量与实时可用性。长期记忆保存跨会话仍有价值的信息，并需要稳定标识、来源、适用范围和有效期。两者共享部分表示，但不应共享全部生命周期规则。一次临时计划可以影响当前回答，却未必适合自动提升为长期事实。

历史版本用于解释变化。某个会议时间被用户修改后，最新检索应返回新时间；查询修改过程时，旧时间仍可能是必要证据。因此，遗忘不能简单等同删除数据库记录。系统将当前可用性与历史保留分开处理，通过有效期和状态控制普通检索，再通过历史接口提供审计。物理删除则属于另一类数据治理操作，需要独立授权与保留策略。

### 2.3 显式演化优先于隐式自动覆盖

已有设计考虑新增、重复、补充、冲突和不确定等关系。关系分类可以交给模型提出建议，但最终写入需要确定性检查。当前实现采用显式演化命令，由调用方选择提升、合并、替代、撤回或暂存等操作。这样可以先稳定存储语义和展示过程，避免一个未校准的关系分类器直接决定长期事实。

显式演化也方便评估错误来源。候选抽取错误、关系判断错误和版本提交错误可以分别重现。若系统把抽取、判断和覆盖合并成一个不可观察模型调用，测试失败时难以定位。后续引入自动关系分类器时，应继续输出同一组受约束命令，并通过现有版本检查写入，而不开放模型直接修改数据库。

### 2.4 分组视图的实际含义

现有方案参考 H-MEM 的组织思路，对长期记忆提供分组视图。目前维护接口返回引用分组，并明确标注未实现语义综合。这个阶段的分组帮助用户理解相关记忆的组织方式，也为后续层级摘要保留入口。它尚不具备完整的层级语义检索和摘要传播能力，不能在报告或界面中画成已运行的多层智能记忆树。

采用这种阶段性实现有工程理由。层级摘要会增加新的派生状态，也会使更新和撤回更复杂。底层事实变化后，相关上层摘要必须重新生成，否则旧信息可能通过摘要重新进入回答。在尚未建立传播与失效测试前，保留可追溯的引用分组更便于保证一致性。

## 3 系统架构与模块边界

### 3.1 核心运行时

`MemoryRuntime` 是应用服务入口，协调存储、短期记忆、长期记忆、检索器和模型端口。HTTP 与 SDK 都调用该入口。运行时负责组织异步步骤和总超时，不承担数据库所有细节，也不把宿主认证逻辑写死在内部。这一粒度适合课程集成，因为宿主可以直接调用领域能力，而无需重新实现记忆维护流程。

模型通过端口接入，提供查询规划、窗口抽取和答案生成等能力。服务可以使用已配置的外部模型，也可以由宿主提供调用适配。测试则注入确定性模型，以便精确控制返回内容和失败时机。模型替换不应改变 Scope、来源结构和演化命令，这些契约属于后端自身责任。

### 3.2 存储作为权威状态

SQLite 保存会话和轮次，也保存记忆、版本及审计信息。数据库是事实状态的权威来源，检索结果和推理缓存都属于派生结果。更新时先满足身份、来源和版本约束，再提交状态。这样可以让重启恢复以数据库为准，而不是依赖前端状态或内存缓存。

原始交互与整理后的记忆并存。原始记录提供证据，原子记忆提供紧凑的检索单位。两者的关联通过来源字段维持。保留原文会增加存储成本，但也允许检查抽取内容是否忠于输入，并在模型升级后重新抽取。当前实现优先保证来源准确性，尚未通过自动压缩或归档策略减少全部原始数据。

合法事件的长度可能超过单条原子记忆字段上限。近期原文进入检索时按两千字符分片，每片保留原轮次、事件位置和精确子串来源。片段标识包含原文偏移，避免重复或不稳定标识。此处理保留长事件尾部信息，并防止合法写入在读取时因字段上限而报错；它不是模型抽取产生的新事实。

### 3.3 HTTP 服务和展示前端

HTTP 层负责请求校验、身份依赖和状态码映射。接口包括会话创建、轮次追加、抽取、检索、回答、记忆演化、历史和维护。前端只访问这些接口，不直接读 SQLite，也不接触模型密钥。此边界使前端能够独立替换，并减少展示代码与核心算法相互依赖。

展示界面承担机制解释。会话视图说明 STM 中有哪些信息，记忆视图展示候选、层级、状态和来源，检索视图展示计划与筛选过程。运行轨迹应来自后端实际返回值。没有执行的步骤不应因动画需要而被补成成功状态。模型未配置、检索无结果或来源不足都应成为可观察的界面状态。

### 3.4 课程 SDK 适配层

适配器只在真实宿主 SDK 存在时导入宿主类型，核心包不依赖 `server.*`。插件导出单例，并在宿主启动时配置共享运行时。检索和生成按 SDK 接口返回字段，流式入口输出标准事件。这种依赖方向避免为独立开发搭建一套假的宿主，同时允许在真实宿主中执行正式契约验证。

课程接口没有显式租户、用户和会话参数。因此适配器使用请求上下文传入宿主已验证身份。宿主需要先认证并授权会话，再创建检索子任务。这个步骤不能省略，也无法只靠插件注册自动完成。若把所有请求绑定到固定用户，虽然演示检索可能成功，却失去了隔离语义。

## 4 数据契约与一致性控制

### 4.1 身份范围与记忆适用范围

Scope 由租户和用户组成，参与存储读取和写入。会话标识用于区分当前工作区。长期记忆还包含适用范围，决定信息是否只对当前会话、某个项目或用户有效。权限范围与语义适用范围需要分别检查。前者决定是否能读取，后者决定读到的信息是否应参与当前回答。

检索器接收的候选已经经过用户范围限制，再检查会话或项目等条件。这样可以避免先在全库计算相关度、再在最终结果过滤身份所带来的风险。缓存键也必须包含身份范围。相同查询文本出现在不同用户下，不应共享可包含个人信息的答案。

### 4.2 稳定请求标识与幂等写入

调用方追加轮次时提供稳定 request_id。相同标识和相同内容重试，应返回原记录而非再次写入。相同标识对应不同内容时，应视为冲突。该规则适用于网络重试，也适用于用户重复点击。它使客户端可以安全重试，而无需猜测前一次请求是否已到达数据库。

回答接口不隐式写入用户查询或模型输出。调用方先保存用户事件，生成后再追加回答事件，并使用新的稳定标识。这会增加调用步骤，但使生成重试与记忆写入分离。如果生成接口同时隐式追加消息，一个客户端超时就可能导致后台重复记录，从而改变抽取窗口和后续上下文。

### 4.3 版本检查与并发更新

记忆演化要求调用方提供 expected_version。存储提交前比较预期版本与当前版本，不匹配时拒绝操作。这样，前端停留在旧页面或两个维护任务并发执行时，不会让后到的旧命令覆盖新事实。版本冲突是需要反馈给调用方的正常状态，不能通过自动重试旧命令绕过。

会话抽取同样需要保护处理水位。抽取窗口形成后，模型调用可能持续较长时间。此时新的轮次可能写入，另一个抽取任务也可能推进状态。提交必须基于窗口对应的会话状态执行检查。只有来源和版本全部有效时，候选与水位才一起更新。模型失败、结构错误或来源不符时，未处理轮次应继续保留。

### 4.4 时间、来源与断言类型

事件时间要求带时区，并统一处理到可比较的时间表示。记忆包含有效期，用于区分当前事实与历史状态。来源记录指向轮次、事件位置和原文引用。抽取结果不能引用不存在的事件，也不能把另一个用户的交互拼接为证据。来源校验在提交前执行，不能只依靠提示词提醒模型。

用户陈述、工具观察和助手推断具有不同证据性质。运行时把近期原文作为可检索内容时保留角色，并分别标记陈述、观察或推断。这样，助手生成的猜测不会因为再次进入上下文就自然变成用户确认的事实。后续生成仍需依据任务语义处理这些区别，单独的字段并不能证明答案已经忠实。

## 5 短期记忆维护机制

### 5.1 有界抽取窗口

短期维护默认每批处理不超过五轮待处理交互，并允许引用最多十五轮已处理上下文。轮次数量只是一道上限，窗口还受 token 估计预算限制。实现先为会话状态、结构和提示预留空间，再加入待处理轮次，最后按剩余预算补充过去语境。这样优先保证新信息被处理，又保留指代消解所需背景。

当前 token 预算采用保守字符计数代理，并非目标模型真实 tokenizer 的结果。该方法便于离线运行，也避免为每个模型引入不同分词依赖，但不能准确计算费用。前端和报告应标注估计值。若后续接入模型真实 usage，需要与预算估计分开保存，不能在一个字段中混用。

当单条工具输出已经超过可用窗口，系统要求拆分或筛选相关内容。直接截断可能丢失关键结论，直接接受则可能使下一次抽取永远超预算。会话状态本身也需要约束，模型返回过长摘要或状态时应拒绝提交，并保留待处理输入。容量控制必须覆盖模型输出，否则摘要增长会反过来挤占新信息空间。

### 5.2 原子候选与来源约束

抽取器从有限窗口返回摘要、状态补丁和候选记忆。候选强调能够独立理解的事实单元，并带有主体、属性、值及来源。原子化便于后续合并和替代。例如，一条交互同时修改会议时间和参会方式，拆分后可以分别更新，避免修改时间时误伤仍有效的地点或方式。

模型输出需要通过结构验证和来源验证。结构验证检查字段和类型，来源验证检查引用是否确实存在于窗口。两者解决不同问题。一个格式完全合法的候选仍可能引用错误原文，因此不能仅因 JSON 解析成功就提交。失败时不推进处理水位，调用方可以修改配置、重试或人工检查原始输入。

真实小集暴露了更正时主体命名漂移的问题。抽取窗口现提供有界的现有事实目录，只选择授权范围内、当前有效且相关的主体与谓词。模型以该目录保持实体字段一致，目录本身不作为新增事实的来源。候选若违反目录对应关系或有效期证据约束，交由原模型至多修复一次。修复后仍不通过则保留待处理交互，不由代码偷偷改写事实。

日期校验区分事件日期和事实有效期。截止日期、预约日期等首先属于事实值，只有原文明确给出生效或失效含义时，才能填入 valid_from 或 valid_to。该规则避免把未来交付日期误写为事实开始成立的时间。它是来源语义的保守约束，仍需要在更多表达方式上测试；一次真实更正通过不能证明覆盖全部自然语言时间关系。

### 5.3 抽取触发与任务责任

轮次追加响应给出是否达到抽取条件及其原因，包括待处理数量和 token 压力。阶段结束或明确纠正属于语义事件，由调用方主动触发抽取。当前设计没有让后台定时任务猜测所有阶段变化，以免在集成前引入无法观察的自动动作。宿主可根据自身工作流决定触发时机。

在抽取前，近期原文仍可被检索，因此短期回答不完全依赖抽取是否完成。这个回退降低了模型暂时不可用对基本记忆读取的影响。不过，原文检索不具备摘要压缩和原子化效果，信息噪声也更大。报告评测时应区分原文路径与抽取后路径，不能把两者混在一个结果集合中分析。

## 6 长期记忆演化与检索

### 6.1 提升、合并、替代与撤回

提升操作将经过判断的候选纳入长期可用范围。是否值得长期保存与内容长度无关，而取决于跨会话价值、稳定性和证据。临时任务安排可能只适合短期范围，稳定偏好或复用经验才有长期价值。当前实现通过显式动作让这些判断可审查，也方便前端展示候选到长期记忆的过程。

合并适用于重复或互补证据，应保留来源和版本关系。替代适用于事实变化，需要让旧状态退出当前检索，同时保留历史。撤回用于明确否定已有记忆。暂存用于证据不足或关系不确定的候选。每种动作都有不同含义，前端不能把它们合成一个没有解释的“优化记忆”按钮。

事实冲突与时间变化也应区分。两条记录给出不同会议时间，可能是一次正式修改，也可能是互相矛盾的未经确认消息。前者可以形成版本链，后者需要待确认状态。模型能够提出关系建议，但最终动作必须带着来源和版本进入确定性存储流程。这是系统保持可追溯性的主要约束。

### 6.2 查询规划与检索视图

检索先形成查询计划，确定短期、长期或联合范围，以及当前或历史时间语义。规则规划能够处理部分近期、历史、比较和汇总提示；配置模型后可使用更丰富的意图规划。规划失败时的处理需要保留警告，不能让用户误以为所有查询都经过了同样的模型分析。

不同视图分别检索后，结果需要合并、去重和排序。词法视图适合直接术语匹配，符号视图适合明确主体和属性，语义视图处理表达差异。未配置嵌入器时，系统明确返回 lexical_baseline。这个标签既用于实验分组，也用于前端解释。没有向量计算的路径不能显示为语义检索成功。

动态 K 根据查询需求与配置上限决定结果数量，并进一步受到 token 预算约束。结果数量多并不一定有利于生成。重复或无关内容会增加输入长度，也可能让模型注意到过时事实。动态预算的目标是保留足够证据，是否改善答案质量仍需用独立真值实验判断。

多字段问题不能被单一符号字段约束完全收窄。真实小集中，“截止日期、数据库和格式”一度只返回数据库记录。修复后，单个主体或谓词匹配不再消除多事实召回所需的其他候选。符号视图继续贡献匹配信息，而联合检索保留多个字段的证据，再由预算与排序控制结果。该调整针对真实失败形成回归，效果仍以独立实验为准。

### 6.3 当前事实、历史事实与检索分数

当前事实检索需要排除已经撤回或失效的内容。历史查询则允许访问相应过去状态，并保留时间解释。对同一主体属性的旧值与新值，如果只按文本相关度排序，旧值可能因与查询文字更接近而排到前面。因而版本和有效期过滤属于检索正确性约束，优先于分数优化。

检索或生成期间即使没有数据库写入，时钟也可能跨过事实生效或到期边界。运行时记录当前候选快照的下一次适用时间变化，在返回结果前再次检查。跨界请求清理相关缓存并返回冲突，要求调用方以当前时间重试。历史时点查询保留指定时间语义，不因现实时间推进而被误判成当前事实查询。

SDK 要求分数处于零到一的范围，以便宿主融合。范围规范并不表示分数已具有统一概率意义。词法重叠分数和向量相似度的含义不同，不能通过归一化就认为两者可直接解释为可信度。后续在真实宿主调节融合权重时，应使用独立开发集，并保留检索模式标签。

### 6.4 实际嵌入服务接口与异常边界

系统新增兼容 OpenAI 请求格式的异步嵌入器，可配置服务地址、模型名称和独立密钥。适配器按批请求向量，检查返回数量、索引、维度、有限数值及非零范数，再归一化并恢复输入顺序。总超时包含锁等待和所有批次，避免每批重新获得完整预算。内容摘要缓存减少重复编码，返回副本防止调用方修改缓存向量。

清理嵌入缓存时推进代际标识，旧请求完成后不能重新填回已经清理的缓存。接口异常映射为明确的服务错误，不把失败解释为空检索。该接口已有隔离测试，但本次真实 DeepSeek 冒烟不包含实际嵌入服务，不能声称真实语义检索质量已验证。

模型规划返回空语义查询或仅含空白文本时，检索回退到原始查询再调用嵌入器。这个边界保证格式合法但信息不足的规划不会静默禁用语义路径。回退仍然遵守身份范围、候选预算及有效期过滤，不能扩大授权候选集合。

## 7 回答组装与推理加速

### 7.1 有依据的回答输入

回答输入由当前任务状态、检索证据、查询和近期轮次构成。证据采用可识别编号，生成内容按编号引用。提示要求区分当前状态、过去事实、计划和未验证推断，并在证据不足时说明缺口。近期轮次按预算选择，避免整个历史直接进入模型输入。

回答完成后解析引用编号，排除超出来源范围的编号，并返回警告。该检查能够发现形式错误，却不能判断某句话是否真的由该来源支持。引用存在性与引用正确性必须分开评价。课程要求的引用准确率或 F1，需要人工标注或独立判断，不能直接使用“编号合法比例”替代。

### 7.2 加速目标与采用的方法

本项目的加速针对推理调用路径。当授权范围、模型实例、会话与完整输入证据相同，重复生成通常没有必要。运行时在检索和上下文组装之后计算摘要键，复用已完成结果。缓存前仍执行授权和检索，所以不会因旧答案存在而跳过当前状态检查。这种方式适合重复展示、重试和重复请求较多的工作负载。

缓存键包含租户、用户、会话、模型实例及输入摘要。摘要覆盖最终 prompt 和检索结果身份信息。只用查询文字作为键会把不同用户、不同会话或事实修改前后的问题混在一起，因此不采用这种简化。完整输入一致的条件较严格，可能降低命中率，但使复用理由更容易验证。

缓存有容量上限和存活时间。最近使用的条目被保留，过期条目被清理。过长的模型响应不进入缓存，避免异常输出长期占据内存。缓存仅属于单个运行时，不承担数据库持久化职责。重启会失去热缓存，这会影响冷启动性能，但不会丢失记忆事实。

### 7.3 并发共享与取消语义

同一输入的并发请求可以共享一个进行中的生成任务。多个等待者接收同一结果，从而减少重复模型调用。一个等待者取消时，其他等待者仍可继续。最后一个等待者离开后，生成任务应被取消并收集其终止状态，避免后台遗留任务和未处理异常。

并发共享不能简单计为缓存命中。命中已完成结果通常不需要等待生成，共享进行中结果仍可能等待剩余模型时间。系统分别记录 hit、shared、miss 和 disabled 等状态，并给出避免的模型调用数。界面可以展示原始生成耗时，但不能把它直接认作每个共享请求节省的时间。

### 7.4 加速的适用条件与限制

该方法不会加快首次模型生成，也不会改变模型内部算子或 GPU 调度。查询或证据变化频繁时，命中率可能较低。检索和上下文摘要本身也有成本，因此总体收益需要按实际工作负载测量。系统保留关闭开关，便于在同样数据和模型条件下比较基线与加速路径。

质量保护应包括写入后失效、事实替代后失效、不同用户隔离和不同会话隔离。缓存错误的风险不只表现为错误答案，还可能表现为已删除内容再次出现。因此，数据删除和缓存清理必须联动，并检查进行中请求。当前单实例机制不能自动解决多个进程之间的缓存传播，这属于后续部署扩展范围。

运行时在读取开始时记录存储代际和会话版本，检索完成及生成发布前再次验证。事实撤回或替代期间形成的旧快照返回冲突，不发布文本或证据。用户数据删除后，原会话不存在则返回未找到，并清理该身份缓存。HTTP 回归在规划和生成两个阶段暂停请求，执行撤回后恢复，确认均返回 409 且不包含旧事实。关闭加速的生成路径也需要经过这些检查，防止只保护缓存命中而遗漏普通生成。

## 8 SDK 集成与异步可靠性

### 8.1 契约映射

课程 SDK 规定插件元数据、能力声明、检索字段及流事件。适配器提供 search、generate 和 generate_stream。检索返回内容、分数、来源标识、片段标识和引擎名。生成返回文本、引用、来源、检索数量与耗时。插件不认领文件索引能力，因为对话事件写入与课程构建层产生的检索文件具有不同生命周期。

模块可以通过宿主额外模块配置注册，也可以通过宿主引擎目录导出单例。运行时需要在宿主启动时配置，并在停机时关闭。插件注册成功只说明对象被发现，不说明数据库、身份和模型都已就绪。完整验收仍需真实探活、检索、生成及多用户请求。

### 8.2 请求上下文隔离

适配器使用 ContextVar 保存当前请求范围。绑定时复制身份对象，读取或返回给调用方时也提供副本。原因是上下文复制会保留对象引用；如果暴露内部可变身份，一个子任务修改对象后可能影响同级任务。副本策略使调用方无法通过修改公开视图改变已绑定身份。

嵌套绑定需要在退出时恢复上一层上下文，异常退出也必须恢复。检索子任务应在绑定之后创建。异步生成器还存在执行时机差异，创建生成器不会立即执行其内容。绑定必须覆盖实际迭代过程，否则生成开始时已经没有身份上下文。集成指南对此给出专门示例。

### 8.3 超时、异常与事件终止

直接 SDK 调用绕过 HTTP 参数校验，因此适配器再次限制查询长度、K 值及超时。超时必须有限且为正数，排除 NaN 和无穷值。检索和生成使用异步超时上下文，异常向宿主传播，由其熔断器记录。适配器不把后端错误改写为空检索结果。

当前 SDK 流为缓冲兼容模式。它先发送开始和状态事件，完整生成后发送一个文本事件，再发送终止事件。普通错误也形成唯一终止事件，且不泄漏内部异常文本。连接取消则传播取消异常，不向已断开的连接伪造完成事件。宿主需要在请求清理路径中处理取消后的聚合状态。

同步存储操作通过线程卸载避免直接阻塞事件循环。不过，异步等待取消不能强行终止已经执行的同步线程。故而超时测试验证的是请求边界和后续状态一致性，不能声称所有底层计算都被即时停止。对长时间阻塞的外部 SDK，还需要其自身超时和连接管理。

## 9 前端展示与可观察性

### 9.1 以机制为中心组织页面

前端需要让观众看见信息如何从交互变为记忆，又如何参与回答。页面组织应与这一顺序一致。会话区展示目标、约束和交互；记忆区展示候选与长期记录；查询区展示计划、证据和回答；轨迹区展示检索模式与加速状态。各部分使用稳定标识关联，避免观众只看到若干互不相连的统计卡片。

记忆卡片应显示状态、范围、版本和来源入口。用户执行替代操作后，旧卡片应能够在历史中找到，当前检索则反映新版本。若只修改卡片文本而不展示版本关系，观众无法判断后端是否真的维护历史。错误反馈也应说明是输入冲突、模型不可用还是网络问题，而不是统一显示“操作失败”。

### 9.2 加速信息的准确展示

加速面板应分别展示检索耗时、生成等待耗时、总耗时和调用复用状态。上下文长度以估计单位标注，并解释截取前后口径。缓存命中、并发共享和关闭状态使用不同文案。只有存在实际比较样本时才显示倍率，单次命中不推导通用性能提升。

演示时可以连续提交同一问题观察热请求，再新增一条会改变上下文的消息并重新提问。后一个请求应重新检查证据并改变缓存键。这样展示的是可验证的失效机制，比单独展示一个很大的加速数字更能说明设计。网络波动可能影响总耗时，所以需要同时展示模型调用是否被避免。

### 9.3 空状态与失败状态

首次启动时没有会话或记忆，页面应引导创建数据。模型未配置时允许原文写入和检索，并清楚说明抽取与生成不可用。空检索不应自动填充示例记忆，演示样例应明确标注且由用户主动加载。这样既保留演示可用性，也避免把静态素材当作真实后端状态。

浏览器验证需要覆盖窄屏布局、表单输入、加载中状态、请求重试和历史查看。前端构建通过只能证明打包没有阻断错误，不能替代这些交互检查。真实浏览器还应观察控制台和网络请求，确认操作确实到达后端，且没有把密钥或数据库路径暴露给客户端。

## 10 评测设计与证据分层

### 10.1 功能测试与研究评测

功能测试验证确定性约束，例如同一请求不重复写入、越权会话无法读取、版本冲突被拒绝，以及超时后不产生不完整状态。测试模型可以精确构造这些场景，适合回归。它们不能证明真实模型抽取质量，也不能代替长期对话任务的答案正确率。报告中应将工程通过率与研究指标分别列出。

课程材料要求直接评估记忆组件，也要求通过下游任务间接评估。直接评估可测候选来源正确性、更新一致性、检索排序和开销。间接评估需要完整查询到回答流程，并有独立答案或任务结果真值。主观评价用于判断相关性和忠实度，应记录评审协议及分歧处理，避免只展示有利案例。

### 10.2 数据与基线

工程数据采用会议安排、项目约束、偏好变化和历史纠正等合成场景。每个场景可以明确列出应检索的记忆标识与不应出现的旧版本，便于验证生命周期。数据还应包含相似名称、多个会话、不同用户和无关消息，防止系统只在单用户单事实情况下通过。

研究基线可以包括近期原文、固定 K 检索、关闭加速的完整系统和开启加速的完整系统。每个比较只改变目标机制，保持模型、数据和其他配置一致。公开数据集如 LoCoMo 或 LongMemEval 可用于外部验证，但需要按其协议准备输入和指标。未执行这些数据集时，报告仅列为后续实验，不填写分数。

### 10.3 指标定义

Hit Rate 判断查询是否至少命中一条相关记忆。MRR 计算第一个相关结果排名倒数的平均值。Recall@K 使用前 K 个结果命中的相关条数除以全部相关条数。Precision@K 使用相关命中数除以前 K 个返回结果数。课程幻灯片对部分指标的文字描述较简略，实验实现应采用明确公式，避免把查全率和查准率混淆。

NDCG@K 需要相关性等级及理想排序，用于评价排名质量。答案正确率需要预设答案或评分规则。引用 F1 需要标注真正支持答案的来源，而不只是检查编号存在。答案忠实度关注内容是否由给定证据支持，答案相关性关注是否回答当前问题。这些指标分别暴露不同错误，不能只保留一个汇总分数。

效率指标记录写入、抽取、检索、生成和总请求耗时。每组报告样本数、并发度、中位数、百分之九十五分位、吞吐和错误率。GPU 显存只有在运行真实本地模型且完成采样时才有意义。使用外部模型接口无法从本服务可靠获知供应方显存，相关字段应标注未测。

### 10.4 加速实验协议

加速实验将冷请求、已完成结果命中和并发共享分开。先执行热身，再交错运行基线与加速条件，减少机器负载和网络时段造成的偏差。保存每次请求的原始耗时与调用计数，避免只留下平均值。若模型具有随机性，还需要检查重复生成的答案变化是否影响质量比较。

正确性检查与性能检查同时进行。每个命中请求都核对身份、会话和来源；事实替代后确认旧结果不被复用；关闭加速时确认模型仍正常调用。测试模型可以验证避免调用的数量和缓存状态，但其模拟延迟只代表设定条件。真实模型的倍率必须另测，并给出费用、网络和缓存分布口径。

### 10.5 当前验证状态

SDK 独立测试已覆盖配置前访问、可用性变化、嵌套绑定、并发隔离、结果字段、生成和缓冲流、错误终止、取消传播及超时。补充测试检查公开身份对象修改、非法参数、零结果、异常后的上下文恢复和单行 JSON。测试使用隔离模块模拟 SDK 类型，仅用于验证适配器行为，不代表真实宿主验证通过。

全套回归、前端构建和性能结果应附在本次交付记录中，并写明运行命令、版本和输出文件。本文不在实现持续变化时固定一个容易失效的测试总数。正式提交时应以最后一次完整运行结果为准，并保留失败后修复的对应测试。缺少宿主或模型的项目应保持未验收状态，不能归入已通过。

### 10.6 已运行实验与失败证据

本地合成评估已在 Windows 11、Python 3.12.14 环境执行，原始数据与口径见 [EVALUATION.md](EVALUATION.md) 及同名 JSON。词法基线在六条正例上得到 Hit@3、Recall@3、MRR@3 和 NDCG@3 均为 0.667。两个改写挑战未命中，说明该结果不能证明语义表达泛化。负例还暴露出词法误召回，需分别检查相关性和权限过滤，不能将任意返回内容都视为命中成功。

在内存候选检索规模实验中，分别使用一百、一千和一万条记忆，每组重复十次。2026 年 9 月 17 日 03:26 UTC 报告的中位耗时为 9.86、79.28 和 892.00 毫秒，对应 P95 为 10.58、91.68 和 933.30 毫秒。这些数值包含内存分配跟踪开销，不包含数据库读取和模型网络请求。它们说明扫描工作量会随候选规模增长，也支持后续优先引入候选索引的工程判断。

加速消融使用人为设置二十五毫秒异步延迟的生成器。十次完全重复请求中，关闭加速调用十次生成器，开启加速调用一次并避免九次调用。两组中位耗时分别为 45.66 和 5.90 毫秒，P95 分别为 47.23 和 46.64 毫秒；加速组包含首次未命中。八个并发同上下文请求也只触发一次生成。这些结果验证调用复用机制，不能转换成真实模型推理倍率。实际服务延迟还包括规划、检索、数据库读取和网络变化，需要分阶段测量。

真实模型首次冒烟曾在抽取阶段收到 HTTP 402。用户恢复上游可用性后，已重新使用 DeepSeek deepseek-flash 完成独立临时库冒烟，最新记录见 [LIVE_SMOKE.md](LIVE_SMOKE.md)。实际抽取形成两条长期记忆，跨会话召回、中文回答偏好和热缓存命中检查均通过。基线、开启加速的冷请求和热请求总耗时分别为 2127.1、1559.5 和 745.8 毫秒，热请求避免一次最终生成调用，规划仍然执行。这只是一次小样本连通性与机制验证，不构成统计性延迟提升或真实问答质量结论，也不替代真实宿主验收。

HTTP 负载使用真实 FastAPI、SQLite 和 ASGI 进程内传输，结果见 [HTTP_LOAD.md](HTTP_LOAD.md)。三十并发下九十次写入和查询的 P95 分别为 80.12 与 85.40 毫秒；一百并发下三百次写入和查询的 P95 分别为 248.86 与 226.53 毫秒。四组失败率均为零。关闭并重开数据库后，九十及三百个会话均恰好保留一轮。实验采用不同会话、先写后查，不包含网络协议栈、模型调用或同会话竞争，不能外推为生产网络 SLA。

### 10.7 真实十题小集与修复复测

新增真实模型小集使用四条合成项目事实、两个项目和两个用户范围。十题包含直接回忆、中文改写、多事实组合、未知预算、隔离，以及更正后的回忆。每题关闭答案缓存，执行一次真实规划和生成。评分采用预先写入脚本的词面与来源检查，没有模型评委。完整回答和来源见 [LIVE_QUALITY.md](LIVE_QUALITY.md)，初次结果保存在 [LIVE_QUALITY_INITIAL.md](LIVE_QUALITY_INITIAL.md)。

初次执行十题均完成，自动规则通过七题。多事实题遗漏日期和格式；更正候选的主体与原事实不一致，未满足精确替代条件，导致后两题继续回答旧日期。候选还把截止日期填为生效日期。这些记录没有删除。修复加入有界事实目录、日期证据检查和至多一次模型修复，并调整多字段召回，随后重新执行同一小集。

复测十题均完成且没有请求错误，自动规则通过九题。更正候选复用原主体与谓词，生效时间未由事件日期推造，显式替代形成版本二。唯一未通过的第九题正确回答当前日期为十二月五日，同时解释原十一月二十日已被替代。保守规则禁止旧日期出现在回答任何位置，因此该题仍记失败。

交付复核由开发代理阅读原文和来源完成，属于非盲检查，没有独立人工评审组。复核确认第九题的日期依据来自有效的新版本，其值为 2026-12-05，并非旧事实仍生效。该说明不修改九分结果，也不追认十分。两次执行只有十题且包含模型随机性，不能将七到九的变化写成统计显著提升或通用准确率。

最终工程回归记录为一百二十一项测试通过，包含新增抽取约束、检索边界与 HTTP 生命周期用例。这一数量说明受控断言通过，不能与真实模型小集分数合并。正式交付保留测试命令、原始评测和失败分析，使评审可以分别判断实现正确性与模型行为。

## 11 交付、部署与风险控制

### 11.1 独立部署的基本条件

部署需要明确 Python 环境、配置文件来源和数据库路径。环境变量优先于本地配置，密钥只在后端保存。启动后通过健康接口确认存储与模型状态，再执行创建会话、写入和检索的真实冒烟。生产模式需要启用访问令牌，但共享令牌只提供服务访问控制，不能自动变成多用户身份系统。

多用户部署应从宿主认证结果创建 Scope，并检查会话归属。浏览器提供的用户标识不能直接作为授权依据。对外访问还需部署层提供 HTTPS、日志保护和密钥轮换。当前实现能支持这些接入点，但最终安全性取决于集成方是否完成真实身份链，不能仅凭本地接口测试宣称已经具备完整企业认证。

### 11.2 备份、恢复与数据治理

数据库备份需要考虑运行中的事务和 SQLite 日志模式，避免只复制主文件而遗漏未合并状态。恢复后应运行完整性检查，并验证会话、轮次、来源和版本链。备份可创建并不代表恢复可用，因此发布前需要用备份在独立目录启动一次服务。任何演示脚本都应使用临时数据库，避免污染用户现有数据。

记忆可能包含个人信息或敏感项目记录。部署方需要确定保留期限、删除权限和审计范围。撤回用于停止当前使用，物理删除用于数据治理，两者应在界面中区分。缓存清理和日志保留也要纳入删除流程，否则数据库中删除的内容仍可能存在于派生存储。

### 11.3 商用交付的适用表述

本项目的交付目标是可运行、可解释、可测试的记忆系统候选版本。它包含独立后端、展示前端、SDK 适配、文档及验证入口。商用上线还需要目标环境容量测试、恢复演练、真实身份接入、依赖扫描和宿主验收。以这些明确门槛描述成熟度，比单独使用“商用级”标签更有可操作性。

当前主要限制包括小规模扫描检索、单实例缓存、未完成的层级语义摘要，以及缺少真实宿主运行环境。这些限制不妨碍验证主线机制，但会影响大数据性能和跨实例部署。后续扩展应保持核心数据契约，优先替换候选检索适配器，而不让外部索引取代权威版本判断。

## 12 结论与后续工作

本项目把既有 SimpleMem 思路落实为两条可观察执行路径。在线路径围绕查询意图、记忆范围和上下文预算组织回答，维护路径围绕来源、版本和有效期形成长期状态。核心运行时与宿主接口分离，使后端能够独立验证，也能以检索和生成粒度嵌入课程 Engine。前端通过实际轨迹展示机制，并保留模型不可用和基线模式等真实状态。

附加实现的推理复用建立在完整输入一致条件下，并保留授权、检索、缓存失效和取消语义。其价值可通过避免的模型调用数及受控延迟实验验证，真实端到端收益仍取决于工作负载和模型环境。下一阶段应完成真实宿主集成，补充独立长期对话数据实验，再按测得瓶颈接入向量候选索引或跨实例设施。最终课程报告、答辩材料和视频应引用这些实际证据，明确区分已实现能力与尚待验证的扩展。
