## 保留并补齐的设计主线

工作区 `output/长短期记忆系统方案汇报/当前设计与框架.md` 定义在线查询和长期维护两条链。本实现继续采用 SimpleMem 式结构化压缩、意图规划、短期优先、多视图检索与动态预算；以证据、作用域和时间演化控制长期事实。

当前补齐了原框架中的④模型关系建议和⑤模型高层摘要。④仅在规则无法安全判断时提供带原文依据的审核建议；⑤在 Domain/Category/Trace 分组内概括来源事实，保留版本引用和覆盖范围，不生成新的权威记忆。H-MEM 风格组织不是完整层级语义搜索复现。

词法路线已引入 FTS5 候选投影和 BM25；向量按内容复用，启用真实 Embedding 时参与余弦召回。仍需读取授权 owner 的权威快照，尚无 ANN 或分布式检索验收。显式实体关系可提供有来源的两跳扩展，不能由模型猜测同名实体或关系。

长期维护提供可恢复归档、衰减建议、摘要生成和缓存失效。独立 HTTP 服务的周期 worker 默认每 300 秒处理当前配置 principal，可通过 `MEMORY_MAINTENANCE_INTERVAL=0` 禁用；课程宿主需要独立决定调度策略。

## 更接近实际使用的案例

| 场景 | 应有行为 | 需要观察的证据 |
|---|---|---|
| 只问“zfc 是飞猪吗” | 不凭问句建立肯定事实；缺证据时拒绝猜测 | 无新增肯定记忆、来源与警告 |
| 明确说昵称，随后询问 | 同会话可调用原始或已抽取证据 | 原始事件位置、短期候选、检索命中 |
| 要求跨会话保存，再开新会话 | 持久候选经校验进入长期记忆并可复用 | 用户作用域、长期层级、来源 |
| 临时修改本次材料语言 | 当前会话覆盖默认规则，不改写用户长期偏好 | local override、作用域、长期版本不变 |
| “从旧名改为新名”与“之前说错” | 前者关闭旧有效期，后者撤回错误说法 | supersede 与 correct 的不同审计 |
| 同一字段出现无解释的不同值 | 进入待决并提示冲突，不按最新文本盲目覆盖 | pending 候选及规则/模型建议 |
| 超过单批的长会话 | 连续分批抽取，历史证据可追溯 | 批次和处理水位，不能跳过中间记录 |
| 抽取超时或演化故障 | 超时不推进抽取水位；提交后故障由 outbox 重试 | 警告、持久任务、重启后的恢复 |
| 归档后恢复、事实自然到期 | 数据可恢复，但过期事实不能重新变成当前有效证据 | revision、防旧页面操作、摘要失效 |
| 相同上下文基线/热请求 | 复用真实生成调用，并展示限制 | 命中状态、实际耗时、避免调用数 |

`test_maintenance.py` 与 `test_practical_core.py` 覆盖生命周期及运行编排；真实模型结果与运行状态统一记录在 [VERIFICATION.md](VERIFICATION.md)。早期 [LIVE_SMOKE.md](LIVE_SMOKE.md)、[LIVE_QUALITY.md](LIVE_QUALITY.md) 和 [EVALUATION.md](EVALUATION.md) 保留历史条件，不能将旧分数直接当作本次新增机制的结论。

## 展示顺序

1. 从无证据提问开始，演示系统没有凭问题“记住答案”。
2. 明确陈述事实，观察 NDJSON 驱动的抽取、规划、检索、生成阶段以及来源连接。
3. 保存长期规则并切换会话，展示跨会话复用；加入临时规则，解释作用域覆盖。
4. 对比现实变更、错误纠正和待决冲突，打开版本与审计。
5. 运行维护，观察三级来源摘要、归档与恢复；说明模型摘要不能当作新事实。
6. 在相同上下文下比较冷/热生成，再改写事实展示缓存失效。
7. 展示长案例、失败恢复与测试记录，并列出公开基准、真实宿主和生产验收的剩余边界。

前端轨迹必须来自真实阶段事件；生成中的动画只表示任务仍在运行，不能伪造检索结果或模型思维内容。当前阶段流不包含隐藏思维链，也不等于逐 token 流式回答。
