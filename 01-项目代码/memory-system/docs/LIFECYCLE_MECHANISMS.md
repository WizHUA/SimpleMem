# 长期维护机制与验证

本次实现沿用本地《Agent 长期记忆：机制、评测与研究空白》中的“写入—整合—读取—更新/遗忘”闭环，以及课程要求的动态更新与遗忘。原始事件和版本化记忆保留为证据；摘要和模型关系建议不能反向充当新的抽取证据。

## 抽取后的演化

`LongTermMemory.process_extraction` 对带用户原文证据、标记为持久、且作用域是用户或项目的已陈述事实执行安全演化：

- 无相同字段：晋升为长期记忆。
- 主体、属性、值、类型、断言性质、作用域和有效期全部一致：合并证据，允许内容措辞不同。
- 同一字段的原文明确包含主体、旧值、新值以及“改为”等现实变更词：关闭旧有效期并建立新版本。未指定有效期时使用该证据事件的时间。
- 原文明确指出“更正、说错、不是……而是”：撤回错误旧版本并建立更正版本，避免把错误说法当作曾经真实的历史事实。
- 其余不同值：候选进入待决状态，保留旧事实。可选模型补充关系类型、理由和逐字证据，仅作为人工审核建议。

问题、假设、推断不能授权自动更正。跨主体、跨作用域的合并不被允许。状态变更使用版本检查、事务和审计；模型失败不撤销已保存的抽取结果。

## 遗忘与恢复

维护计算可解释的年龄—证据衰减分数：事件、事实、偏好、流程的基础半衰期分别为 30、180、120、365 天；独立证据事件最多提供三倍强化。该分数是策略启发式，不是事实可信度。

已过有效期的事件自动转为可恢复的归档状态。衰减较强的稳定事实只产生归档建议，不自动删除。归档保留原文、版本和审计，可以恢复；恢复不修改有效期，过期事件仍不能作为当前有效事实返回。隐私删除是独立操作，不能与衰减归档混为一谈。

## 分层摘要

Domain、Category、Trace 各层均建立带来源版本的提取式摘要，每组最多展示 12 项、1600 字，报告省略数量。配置模型时，最多处理 8 组，并共享 30 秒总预算；模型只接收有界输入，输出必须引用本组提供的实际版本。

模型摘要是导航视图，引用合法不等于语义逐句蕴含已验证。它不新增 Memory，也不用于证明新的事实。源记忆更新或撤回时摘要失效；来源未变时复用已保存摘要。覆盖数量与组内总数量随摘要记录，避免把部分摘要误报成完整概括。

## 验证

`tests/test_maintenance.py` 覆盖昵称跨次保存、重复措辞、未解释冲突、现实改名、错误纠正、问题/假设拒绝、事件归档恢复、衰减建议、逐层摘要来源、摘要缓存失效，以及模型失败或越界输出。

这些机制不等于无约束的自动知识融合。别名消解、开放域语义等价和多来源矛盾裁决仍应经过明确的证据或审核；保留待决结果比自动固化猜测更适合真实使用。
