# 对话与证据交互设计

这是一套有记忆的对话系统。首屏让用户继续对话；系统机制在回答旁可检查，记忆管理作为可收起的侧栏。

- 色彩：纸白 #ffffff、雾灰 #f5f7f9、墨蓝 #233748、次级灰 #75818d、记忆青 #297e83、提示琥珀 #a8702d。
- 字体：系统中文无衬线，正文 16px / 1.85；过程 12–13px，灰色但保持可读对比；编号引用 11px。
- 版式：左对话、右检查器；收起检查器后对话居中、最大阅读宽度 800px。助手不套大气泡，用户消息保留浅灰背景。
- 个性：展开处理过程后，短期与长期记忆以曲线汇入证据节点，再流向回答；只对服务已经到达的阶段点亮，不伪造推理或百分比。

```
SimpleMem                         模型状态    记忆面板
              用户问题
✧ 已完成检索 · 0.8 秒  ⌄
  [展开：实际查询 / 记忆汇流 / 阶段记录 / 回放]
直接回答问题。¹ ²
[输入框                                       发送]
```

自检：删除原先抢占顶部空间的五个阶段框，避免通用仪表盘感；保留一个精致的证据汇流图作为识别点。动效仅用于进行中的轨迹与用户触发回放，尊重 reduced-motion。

来源编号解析 Markdown 文本节点，不碰代码和现有链接。弹窗显示回答时的来源快照、原文证据、版本与作用范围；旧回答缺少快照时明确提示，不关联最新回答来源。原生 dialog 提供焦点约束、Escape 和返回触发点。过程说明是真实服务操作摘要，不展示或模拟模型内部思维链。

## 三路检索可视化增补

将原来的短期/长期两池图改为三路读库视图：查询计划分出语义（紫灰）、词法（青）、符号（赭）三条路径，与短期库、长期库分别连接；返回后经过融合去重、动态 K 和上下文预算筛选，落到可点击的证据。

视图必须与 `_recall` 的真实逻辑一致：先处理短期，必要时补长期；词法/符号在同一 CPU 任务执行后才进行可选语义召回，不用并行动画暗示三路同时运行。双向线表示查询与结果返回。只有 `channels.status=complete` 或真实入选来源标明匹配通道时才点亮；语义未配置显示“未配置向量服务”，不模拟执行；完整主体/属性缺失的符号通道显示跳过。历史记录缺少完整通道统计时保留未知，不从最终结果反推候选数量。

通道按钮展开方案说明和分库检查/命中/入选数。命中数为各通道截断前记录，同一事实可命中多路，不将总次数伪装成去重候选量。动态 K 使用后端 `dynamic_k` 的规划深度、信息需求、目标 K、候选上限与实际上下文预算。最终阶段前不把暂时的 `selected_count=0` 当作最终值。

图形采用 HTML 可读标签叠加 SVG 曲线，文字保持真实 CSS 字号。容器小于 610px 时切为纵向通道和两库台账，避免整体 SVG 缩小导致小屏字难读。键盘可选通道，来源延用已有弹窗；reduced-motion 关闭动态线路。
